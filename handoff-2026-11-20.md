## What happened this session
1. **Lost admin login.** Passwords can't be recovered (Supabase keeps only a bcrypt hash). The app has no reset flow, so the password was reset directly in the Supabase SQL Editor:
   ```sql
   -- find users
   select cm.username, cm.full_name, cm.role, u.email
   from company_members cm join auth.users u on u.id = cm.user_id
   order by cm.role;

   -- reset a password (quote both values)
   update auth.users
   set encrypted_password = extensions.crypt('NEW_PASSWORD', extensions.gen_salt('bf'))
   where email = '<synthetic email from query above>';
   ```
   Result: Cristian can log in again. The same method works for any worker who is locked out.
2. **Supabase outage around 2:47 AM.** Postgres logs filled with `57P03 the database system is shutting down`, and the project briefly showed **Unhealthy**. It recovered by itself within minutes to **Healthy** (CPU 0%, Disk 3%, RAM 31%, 7/60 connections). Most likely a platform restart or maintenance, not caused by the app. During the outage, the app's 30-second sync polling produced most of the error lines.
